# Vision: видение продукта

Версия 1.0: 20.10.2026.

## Для кого делаем систему

Для сотрудников ПВЗ, супервайзеров региона и операционного аналитика сети. Заказчик проекта - Борис Максимович Фёдоров. Общение с Заказчиком ведёт Владимир.

## Какую проблему решаем

Сотруднику нужно учитывать движение отправлений и быстро находить их на хранении. Супервайзеру нужно понимать, какие точки и часы перегружены, а где есть свободные возможности. Для этого нужны связанные данные об операциях, расписаниях и допустимой нагрузке.

## Наш продукт

Система ПВЗ - сайт, через который сотрудник принимает, выдаёт и возвращает отправления, размещает их в ячейках и готовит возвраты к отгрузке. В 1С по этим данным строится отчёт «Загрузка ПВЗ». Супервайзер сравнивает точки своего региона, а операционный аналитик смотрит данные всей сети.

Главная ценность - соединить повседневный учёт отправлений с понятной картиной загрузки ПВЗ. Система показывает факты для решений о сотрудниках, продвижении и распределении потока. Она не меняет рекламу автоматически и не обещает сокращение очередей без проверки результата.

## Что получим к декабрю

К 1 декабря 2026 года работает MVP:

1. Приёмка по коду с размещением в ячейке.
2. Выдача по коду получения.
3. Приём возврата по коду возврата.
4. Формирование и подтверждение отгрузки возвратов.
5. Отчёт о загрузке с фильтрами, диаграммами и CSV.

Также работают вход, права, расписания, проверка объёма ячеек и журнал операций. Коды вводятся вручную. Данные - тестовые. Сервер - Java/Spring Boot, основная БД - PostgreSQL, отчётность - 1С.

## Что получим к маю

Полная учебная версия включает работу сразу с несколькими отправлениями, сроки хранения, сверку наличия, сравнение загрузки и рекомендации супервайзеру с указанием данных, на которых они основаны. Обмен с 1С становится удобнее. Разработка, защита и исправления завершаются не позднее 31 мая 2027 года.

## Границы и оценка результата

Не подключаем реальные маркетплейсы, сканеры, терминалы, платежи и геосервисы. Не используем персональные данные клиентов. Сотрудник работает со своей точкой, супервайзер - со своим регионом, аналитик - со всей сетью.

Результат проверяем по [метрикам успеха](card.md#3-kpi-и-критерии-успеха) и [критериям приёмки](acceptance.md). Все обязательные функции MVP должны пройти проверку; отчёт должен совпадать с эталоном. Подробные границы приведены в [карточке проекта](card.md#4-границы-mvp).
