# ADR-001 Снимок CSV для отчёта 1С

**Дата фиксации:** 15.11.2026. Решение описывает существующую договорённость в проектных документах. Серверная выгрузка и её ограничения по ролям реализованы и проверены. Импорт и отчёт в 1С ожидают проверки. [Контракт файлов](../../spec/schema.md).

| Требование | Архитектурное решение | Проверка |
|---|---|---|
| [IF-02](../requirements.md#if-02), [DR-04](../requirements.md#dr-04) | Сервер читает согласованный срез PostgreSQL и формирует комплект CSV UTF‑8 с номером снимка и временем. Конфигурация 1С загружает и проверяет комплект целиком через свою форму. | [AC-07](../acceptance.md#ac-07) |
| [FR-10](../requirements.md#fr-10) | Операции импортируются по уникальному `op_id`. При ошибке проверки предыдущий снимок остаётся доступен для отчёта. | [AC-01](../acceptance.md#ac-01), [AC-07](../acceptance.md#ac-07) |
| [DR-05](../requirements.md#dr-05), [FR-08](../requirements.md#fr-08) | Снимок включает расписание, мощность и временные метки операций. 1С считает нагрузку по рабочим часам в Europe/Moscow на данных этого снимка. | [AC-06](../acceptance.md#ac-06) |

Отчёт 1С работает на зафиксированном наборе данных. Сайт продолжает выполнять операции во время недоступности 1С. Номер и время последнего принятого снимка показывают актуальность отчёта. Повторный импорт и отказ с сохранением предыдущего набора проверяются при приёмке.

Пакеты [WP-API](../work-packages.md#wp-api) и [WP-1C](../work-packages.md#wp-1c). Выполнение проходит через [T-02](../delivery-plan.md#t-02), [T-09](../delivery-plan.md#t-09) и [T-10](../delivery-plan.md#t-10). На [C4 L2](../c4-container.md) обмен показан пунктирной связью от API к 1С.
